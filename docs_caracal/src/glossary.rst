.. _glossary-terms:

Glossary
========


.. Custom attributes — set once, reuse via |name|
.. |caracal| replace:: Caracal
.. |boom| replace:: BOOM
.. |isa| replace:: RV64GC

.. glossary::
   :sorted:

   uOP
      A decoded instruction packet — the unit that flows through the |boom|
      pipeline. The |caracal| decoder is single-cycle combinational and emits
      exactly **one** uOP per instruction; it performs no cracking or micro-op
      expansion, so a vector instruction is also a single uOP (see :term:`OP.v`).

   OP.v
      A **vector** uOP — a uOP with ``is_vec`` set, carrying the vector-specific
      ``MicroOp`` fields (``pvs1/pvs2/pvs3``, mask ``pvm``, ``v_eew``/``v_emul``,
      and the ``vconfig`` snapshot). A single OP.v represents an entire
      ``LMUL``/``EMUL`` vector-register group and occupies **one** ROB entry — it
      is not cracked into one uop per destination register at decode.

   nOP.v
      A **nano-vector** OP — generated by cracking of load/store OP.v's in the
      Vector LS AGEN stage. These are memory operations that are at the vector
      element granularity level. |caracal| performs **no frontend cracking**: an
      :term:`OP.v` stays a single uOP through decode/rename/ROB/issue and is only
      expanded into nOP.v inside the Vector LS AGEN. The ``MicroOp`` element/segment
      cursor fields (``v_split_first/last/idx/total``) are therefore **nOP.v-scoped** —
      inert on the OP.v itself and populated only when the AGEN emits element accesses.
      They are *not* frontend-cracker state.

   Scheduler
      |caracal|'s **single** issue stage. The scalar queues
      (``IQ_MEM``/``IQ_UNQ``/``IQ_ALU``/``IQ_FP``) are unchanged from |boom|;
      |caracal| adds three vector queues (``IQ_V_LOAD``/``IQ_V_STORE``/``IQ_V_ALU``).
      **All** of them are **age-ordered collapsing** (grant oldest-ready); ``IQ_V_ALU`` differs only
      in adding a **per-entry** :term:`past-PNR` eligibility gate (RoCC-style), so every op it hands
      to the CII is individually non-speculative. A **non-shared** :term:`OP.v` occupies **one**
      slot, and each slot is granted **once**, when
      **all** of its operands are ready — scalar feeders (base/stride/``.vx``) on the integer
      network, ``pvl`` on the VL network, and vector registers (``pvs*``, mask ``pvm``) on the
      vector network. Only the ``IQ_V_*`` queues connect to the vector wakeup network.

      **"Granted once" is per issue slot per execution path, not per ``OP.v``.** Two cases make the
      distinction matter: a :term:`shared instruction` occupies **two** slots and each is granted
      once, and a vector **store** slot's AGEN and DGEN paths are **independently grantable** — for
      a segmented store, hundreds of cycles apart (see :ref:`shared-store-chain`). The invariant the
      phrase names is that an ``OP.v`` is allocated and selected **once**, with no second issue
      stage and no second priority-encoder select.

   past-PNR
      A ROB entry older than ``rob.io.rob_pnr_idx`` — i.e. every instruction older than it is
      *safe* (cannot mis-speculate). ``IQ_V_ALU`` grants only past-PNR entries, which is what
      removes **branch**-kill from the coprocessor: ``is_br``/``is_jalr`` set ``starts_unsafe``,
      so the PNR never sweeps past an unresolved branch.

      .. warning::

         Past-PNR is **not** a commit guarantee. A ROB-head flush —
         ``MINI_EXCEPTION_MEM_ORDERING``, ``MINI_EXCEPTION_CSR_REPLAY``, an exception, or an ERET —
         can squash past-PNR work, because a load's ``rob_unsafe`` bit clears on its first address
         translation while ``order_fail`` is discovered later. See :ref:`cii-flush`.

   group-done
      The **single** completion event a vector producer emits per ``OP.v``, carrying the completing
      destination group's full **member-PRN vector**. One event drives all three consumers at once:
      the ROB's single-shot ``rob_bsy`` clear, the vector Busy-Table clear, and the vector wakeup
      network. Loads emit it from the :term:`LCB` after the last destination PRN lands; the CII
      emits it on the writeback beat marked ``last``.

   stale_pvdest
      The physical group that held the destination architectural vector register **before** this
      ``OP.v`` renamed it. It is the **only** source of undisturbed lanes anywhere in the machine —
      ``vta = 0`` tail, ``vma = 0`` masked-off, and any ``vstart > 0`` prefix — because ``pvdest``
      is always a *fresh* group. Read by the LCB on VRF port ``R2`` for loads, and pulled by the
      coprocessor on the ``STALE_VD`` operand slot for arithmetic. Freed as a whole group at commit.

      **Distinct from ``pvs3``**, which is an *explicitly encoded* third source operand. The two
      name the same group for read-modify-write arithmetic (``vfmacc``) and different groups
      whenever an op needs old-``vd`` for merging without encoding a third source (masked
      ``vadd.vv`` under ``vma = 0``, ``vslideup``, ``vcompress``). They are separate ``MicroOp``
      fields and separate CII source slots; the coprocessor decides which to pull, and pulls both
      when they differ. See :ref:`old-vd` and :ref:`cii-operands`.

   pvtmp
      The intermediate vector register group allocated by the vector mapper for a
      :term:`shared instruction`, through which the LSU and coprocessor halves rendezvous. It is an
      **ordinary VRF group** — no separate temp register file — with a real busy lifetime, reclaimed
      on mispredict and freed at commit alongside ``stale_pvdest``. Never installed in the vector
      RMT, so no architectural read can alias it.

      The binding is held in the ``OP.v``'s own **``pvtmp`` ``MicroOp`` field**, written by the
      vector mapper at rename. Both halves derive from that single uop and single ROB entry, so each
      half's issue slot carries the member PRNs directly and no RMT entry is needed — which is
      exactly why excluding it from the RMT costs nothing.

   shared instruction
      An ``OP.v`` marked ``is_shared`` that needs **two** execution resources: one issue slot in
      ``IQ_V_ALU`` (coprocessor half) and one in ``IQ_V_LOAD``/``IQ_V_STORE`` (LSU half), but a
      **single** ROB entry. Currently only segmented load/store. The halves hand off through
      :term:`pvtmp` and always complete producer-half-then-consumer-half.

   LCB
      Load Coalescing Buffer — the ``VLEN``-wide assembly structure in front of the VRF write port
      that turns out-of-order, ≤ ``ELEN`` per-element cache responses into **one VRF write per
      destination PRN** and **one** :term:`group-done` per instruction.

   is_vl_producer
      A ``MicroOp`` bit, **orthogonal to ``dst_rtype``**, marking a uop that writes the VL register
      file. Required because a ``vset`` has two destinations in two independent rename spaces
      (``pdst`` in the integer RF, ``pvl`` in the VL RF) and ``dst_rtype`` is single-valued — with
      ``rd == x0`` it reads ``RT_ZERO`` while the VL RF is still written. See
      :ref:`the dual-destination rule <vset-dual-dest>`.

   VCFG mirror
      The **speculative, decode-stage** copy of ``vtype`` that lets younger vector uOPs derive
      ``EMUL`` (and snapshot ``vtype``) without a CSR read. Not architectural state: it is
      branch-snapshotted per ``br_tag`` and recovered from the **committed VCFG shadow** on any
      flush. A ``vill``-setting ``vset`` must **poison** it so younger vtype-dependent uOPs trap at
      decode rather than allocating a mis-sized PRN group. See :ref:`vector-csr-ownership`.

   reservation
      Capacity in a vector element queue claimed **in program order at dispatch**, sized to the
      worst-case active element count from ``EMUL``/``EEW``, with the surplus released at execute
      once ``VL`` is known. It provides two unrelated properties: deadlock freedom for stores
      (:ref:`ssi-queues`) and squash-by-pointer-rollback for all four queues (:ref:`vec-squash`).

   AGEN
      Address generation — the functional-unit operation (``FC_AGEN``) that
      computes a memory access's effective address in the LSU path. In |caracal|
      vector load/store uop's reuse the scalar AGEN/DGEN machinery to generate the
      per-element/segment addresses of a strided, indexed, or segment access.
      (DGEN, ``FC_DGEN``, is the store-data-generation counterpart.)

   RMT
      Rename Map Table — the structure mapping architectural register numbers
      (ARNs) to physical register numbers (PRNs).
